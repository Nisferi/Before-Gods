# SECURITY.md — Политика безопасности

## Что никогда не должно попасть в Git

| Категория | Примеры |
|-----------|---------|
| Переменные окружения | `.env`, `.env.local`, `.env.production` |
| Ключи и сертификаты | `*.key`, `*.pem`, `*.p12`, `*.pfx` |
| Секреты и токены | `secrets.*`, `tokens.*`, `*.secret`, `*.token` |
| Приватные заметки | `private/`, `notes/private/`, личные идеи вне `GAME_DESIGN.md` |
| Резервные копии | `*.bak`, `*.backup`, `*.orig`, `*.zip` с данными |
| Кеш Godot | `.godot/` |
| Экспортные ключи Godot | keystore-файлы для Android, provisioning profiles для iOS |

Все эти паттерны уже добавлены в `.gitignore`.

---

## Как проверить перед коммитом

```bash
# Проверить, не попадёт ли .env в коммит
git check-ignore -v .env

# Просмотреть все файлы, которые войдут в коммит
git status
git diff --cached

# Убедиться, что .gitignore работает
git ls-files --others --exclude-standard
```

---

## Если секрет всё же попал в Git

1. **Немедленно** отозвать/перевыпустить скомпрометированный ключ/токен
2. Сообщить владельцу репозитория
3. Использовать `git filter-branch` или `BFG Repo Cleaner` для удаления из истории
4. Force push (только `main`-владелец, после согласования)

> Важно: удаление коммита из истории не гарантирует безопасность, если репозиторий
> был публичным или кто-то успел его склонировать.

---

## Сообщить об уязвимости

Если вы нашли уязвимость в коде или утечку данных:

1. **Не создавайте публичный Issue**
2. Свяжитесь с владельцем репозитория напрямую
3. Опишите: что найдено, где, потенциальный impact

---

## Для AI-агентов

- Перед каждым коммитом проверять `git status` и убеждаться, что нет секретов
- Если агент видит файл с секретом — **не коммитить**, немедленно сообщить пользователю
- Агенты не имеют права читать или передавать содержимое файлов из категорий выше
