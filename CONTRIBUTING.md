# CONTRIBUTING.md — Правила участия в разработке

---

## Для людей

### Ветковая модель

```
main        ← стабильный релиз (защищён)
└── dev     ← основная разработка
    ├── feature/название    ← новые функции
    ├── fix/название        ← баг-фиксы
    └── agent/название      ← работа AI-агентов
```

### Процесс работы

1. Создай ветку от `dev`:
   ```bash
   git checkout dev
   git pull origin dev
   git checkout -b feature/название-функции
   ```

2. Разрабатывай в своей ветке

3. Перед коммитом проверь:
   ```bash
   git status        # нет ли лишних файлов
   git diff --cached # что войдёт в коммит
   ```

4. Создай Pull Request в `dev` (не в `main`)

5. `main` обновляется только через PR из `dev` после проверки

---

### Стиль коммитов

```
feat: добавить систему диалогов
fix: исправить коллизию у игрока
docs: обновить ROADMAP
chore: добавить .gitattributes
refactor: вынести логику AI в отдельный модуль
```

---

### Godot-специфично

- Сцены: **текстовый формат** `.tscn` (не бинарный)
- Ресурсы: **текстовый формат** `.tres`
- Не коммитить папку `.godot/` (кеш движка)
- Коммитить файлы `.import` (настройки импорта ассетов)
- Именование файлов: `snake_case` для скриптов и сцен

---

## Для AI-агентов

Смотри [AGENTS.md](AGENTS.md) — там полные правила.

Кратко:
- Работать в ветке `agent/описание` или `claude/описание`
- Никогда не пушить в `main`
- Перед коммитом проверять наличие секретов
- При сомнениях — спрашивать, не угадывать

---

## Что не принимается

- Прямые пуши в `main`
- Коммиты с секретами, токенами, ключами
- Бинарные `.tscn`/`.tres` файлы (только текстовый формат)
- Код без связи с текущими задачами в `TASKS.md`
- Large binary assets без обсуждения (используй Git LFS если нужно)
